5. Student — how they use it

Full screenshots: student guide.

  1. Wait until faculty says the session is open.
  2. Open the platform → Participant.
  3. Enter Student ID, Your name, Password → Sign in.
  4. Play only the assigned simulation through every round.
  5. Finish so completion + KPIs land on the instructor board (one completion per session unless reset).
  • Do not refresh to retry after finishing.
  • Zenith may open a separate tab — stay there until done.

6. Instructor — how they use it

Full screenshots: instructor guide.

  1. Platform → Instructor / Admin → e.g. FACULTY / faculty-demo.
  2. Open session → pick Mumbai / Zara / Zara-new / Zenith.
  3. Tell students it’s live; share only platform + student guide + IDs.
  4. Watch Class scores & history on the console (~6s refresh) or open Live dashboard.
  5. Click a student for report card + round timeline / KPIs.
  6. Past sittings: Session dropdown. Reset runs clears that sitting’s logs for another attempt. Or Close → Open for a new Sess_* (keeps history).
  7. Close session when done. Login persists in localStorage until Sign out.
Only one session open at a time. Wrong title mid-class locks students to that sim.

7. Owner / ops — Sheet & Apps Script

Canonical write-up also in repo: tools/CLASSROOM.md. Same steps below so this HTML stands alone.

7.1 Create the Sheet

  1. Create a Google Spreadsheet named Simulok Classroom.
  2. Rename first tab to Roster.
  3. Import tools/classroom-roster-sample.csv (keep header row).
  4. Add empty tab Sessions (or let the script create it).
  5. Change passwords before a real graded class.

7.2 Deploy Apps Script

  1. Sheet → Extensions → Apps Script.
  2. Paste tools/classroom-session.gs. Save.
  3. Deploy → New deployment → Web app: Execute as Me; Who has access: Anyone.
  4. Authorise (unverified app — continue). Copy the /exec URL.
After any edit to classroom-session.gs: Manage deployments → edit existing → Version New version. Keep the same URL. A brand-new deployment changes the URL and breaks the platform until you update ENDPOINT.

7.3 Wire the prototype

  1. Set ENDPOINT in assets/js/classroom.js to the /exec URL.
  2. Commit → merge to main → Pages deploys (~1 min) → test on /platform/.
  3. Locally: reload root index.html after changing the endpoint.

Current live endpoint is the one already in assets/js/classroom.js on main (do not paste it into decks).

7.4 What the backend does

  • Login (instructor / student), open/close session, list sessions
  • Per-round log + completion with display_name
  • Dashboard payload (roster, leaderboard, rounds / KPIs from extra_json)
  • reset_runs — clear data rows on selected session tab

10. Run a live sitting (checklist)

  1. Sheet + Apps Script deployed; ENDPOINT on main matches.
  2. Passwords set for this cohort (or sample OK for rehearsal).
  3. You (or faculty) sign in as instructor → Open session → correct sim.
  4. Students get: platform + student guide + IDs; ask for real names.
  5. Open Live dashboard on projector (same browser as FACULTY login).
  6. After class: Close session. Next cohort: Open again → new Sess_*.
  7. Retake same sitting: Reset runs. Graded retake with history: Close → Open new session.

13. Troubleshooting

Instructor login hangs / timeout

Check Apps Script deployment is “Anyone”, redeploy New version, confirm ENDPOINT matches. Hard refresh. Sign out and back in.

“Already completed”

Reset runs on that session, or open a new sitting.

Dashboard asks for instructor sign-in

Sign in as FACULTY on the platform in the same browser first (localStorage).

Names show as MBA01 only

Students must fill Your name on Participant login.

Scores not appearing

Session open? Correct sim? Student finished all rounds? Sheet tabs updating? Network / CORS — client posts text/plain JSON string to Apps Script.

After editing .gs nothing changed

You must redeploy a New version of the existing web app deployment.
