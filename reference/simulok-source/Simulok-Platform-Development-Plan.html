01 — Product

A signed-in learning portal, not a zip file.

Professors, students and college admins sign in, see only what their institution is entitled to, play simulations, and keep a record of judgement — attempts, scores, debriefs.

Today the playable library is a single-file shell: strong pedagogy, no real accounts, no persistence, no college tenancy. Phase 1 replaces that with a multi-tenant app and goes to market with 6 MBA titles. After the first college is live, adding a title is mounting a new script onto the same shell. That is how we start earning without waiting to finish every pack.

Must do on day one

  • Student — log in, see assigned sims, play, finish, view history and feedback.
  • Faculty — CSV roster, cohort, assign with dates, watch progress, export scores, run multiplayer (join codes, timers, force-advance).
  • College admin — create the institution, entitle which sims it may use, manage users.
  • Simulok operator — publish a pack and enable it per college without redeploying the whole app.

Not in Phase 1

  • Mobile apps, LTI / SCORM, payments.
  • AI tutor, unique UI per simulation.
  • Inventing new engine maths — that lives in the script.
  • White-label, 24/7 SLA, second AWS region.

03 — How we build

Everyone on Cursor Start (India). Not Pro.

₹649 per person per month, tax-inclusive, UPI or Indian cards, Indian phone verification. Agent, Plan, Ask, Cloud Agents, Cursor models (Grok 4.6 / 4.5, Composer 2.5). If a seat exhausts the monthly pool, that person switches to Composer for mechanical pack work — we do not assume a Pro upgrade in this budget.

What Cursor shortens every week

  • Plan — break a script into a pack checklist before code.
  • Agent — CDK, API handlers, pack JSON, golden tests, faculty CSV import.
  • Cloud Agents — overnight PRs for MCQ extraction; human reviews scoring.
  • Founder Ask — “does this pack match section 4 of the script?”

What AI does not shorten

  • A real classroom — late joiners, Wi-Fi, the bell. That week stays.
  • Multiplayer session lifecycle. Cursor drafts; humans debug live.
  • DNS / TLS waits, college timetables, founder sign-off against the script.

Tooling for 3 seats × 3 months ≈ ₹5,850. A few thousand rupees, not a lakh-line. Calendar shrinks because we launch 6 titles, not 15 — and because packs get faster. Not because we skip the classroom.

Steady state: about one new MBA title a week. A month of part-time engineering after launch is 3–4 titles, paid for by the first college, not by delaying Phase 1.

Seven steps — every new title

  1. Script gate. Rounds, choices, effects, KPIs, scoring, debrief, 2–5 golden paths. If blank, it is not in engineering this week.
  2. Pack from template. Copy the closest live pack of the same format. Folder = sim_id (e.g. heliogrid). Fill manifest.
  3. Cursor Plan. Script → section-by-section checklist mapped to content.json (and engine methods if not MCQ). Human accepts before Agent writes.
  4. Agent implements 1:1. Narrative and tables in content.json. Engine only if not MCQ. Do not fork the shared UI.
  5. Validator + golden tests. Schema must pass. Scripted paths must produce the script’s numbers. Fix mapping; do not tune the model.
  6. Publish a version. CI uploads sim_id @ v1. Live classes stay on the version they were assigned.
  7. Entitle, assign, play, enable. Admin toggle → faculty test cohort → founder plays once → real cohort. Students only see what they are assigned.
